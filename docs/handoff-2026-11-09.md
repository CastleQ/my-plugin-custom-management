# 작업 인계 문서 (2026-11-09)

이 문서는 claude.ai 일반 대화에서 논의한 내용을 Claude Code 새 세션으로 넘기기 위한 기록입니다. 새 세션의 Claude는 이 문서를 먼저 끝까지 읽고 작업을 시작합니다.

---

## 1. 사용자에 대해 (작업 방식에 영향을 주는 것만)

- **비개발자**입니다. 코딩은 취미 수준이고 전문 교육을 받지 않았습니다. 설명은 전문 용어 없이 쉬운 말로, 꼭 필요한 용어는 풀어서 설명합니다.
- 모든 대답은 **한국어**, **결론 먼저(두괄식)**.
- 답변 끝에는 `---`로 구분한 뒤, 사용자가 아직 인식하지 못했지만 실제로 필요한 후속 아이디어나 다음 작업을 질문 형태로 덧붙입니다. 형식 채우기용 억지 제안은 하지 않습니다.
- 단순 비서가 아니라 **조언자**를 원합니다. 사용자의 가정에 허점이 있으면 근거와 대안을 들어 짚습니다.
- Claude Code는 **항상 데스크톱 앱에서 클라우드 세션(GitHub 리포 연결)** 으로만 씁니다. **로컬 세션은 쓰지 않고 앞으로도 쓸 계획이 없습니다.** 여러 PC와 폰을 오가며 같은 작업을 이어갑니다.

## 2. 이 리포의 목적

1. **공통 플러그인·스킬의 단일 관리처**: 모든 바이브코딩 리포와 대화 세션에 공통 적용할 플러그인·스킬을 이 리포 하나에 모아 관리합니다.
2. **세션 시작 브리핑**: 작업 세션에 지금 적용된 플러그인 목록을 사용자가 아무 명령도 하지 않아도 매번 볼 수 있게 합니다. 의도는 두 가지입니다.
   - 어느 리포에서 어떤 플러그인이 빠졌는지 확인
   - 설치해놓고 잊은 채 안 쓰는 플러그인이 있는지 환기 (맥락 환기)

## 3. 지금까지 확인한 사실 (근거 포함)

### 3-1. 왜 "패널(mod)"이 아니라 "첫 답변 표"인가
- 사용자는 처음에 데스크톱 앱 우측에 커넥터 목록처럼 플러그인 목록 패널을 띄우고 싶어했습니다. 이를 위한 기능이 Claude Code **mod**(v2.1.287, 2026-10-01 출시)입니다.
- 그러나 공식 문서의 "Where mods run" 표에 따르면 **클라우드 세션에서는 mod의 코드(훅)는 돌지만 mod가 그리는 화면은 표시되지 않습니다.** 사용자는 클라우드 세션만 쓰므로 패널 방식은 불가능합니다.
  - https://code.claude.com/docs/en/plugins/mods/overview (Where mods run)
- 그래서 **세션 시작 훅(SessionStart) → 플러그인 목록 수집 → Claude에게 "첫 답변 맨 위에 표로 보여줘"라고 지시**하는 방식으로 합의했습니다.

### 3-2. 왜 이 리포를 "개인 플러그인 마켓"으로 만드나
- 클라우드 세션은 **사용자 PC의 사용자 설정(`~/.claude/settings.json`)에만 켠 플러그인을 가져오지 않습니다.**
  - https://code.claude.com/docs/en/claude-code-on-the-web
- 클라우드 세션은 **작업 리포의 `.claude/settings.json`에 적힌 `extraKnownMarketplaces`를 추가하지 않습니다**(작업 폴더 신뢰 확인 창이 필요한데 클라우드 세션은 그 창을 띄우지 않음). 리포가 켜둔 플러그인이 설치되지 않는다는 이슈 보고도 있습니다.
  - https://code.claude.com/docs/en/plugins/loading
  - https://claudeissues.com/issue/88214
- 반면 **claude.ai 계정에서 켠 플러그인은 `이름@synced`로 Claude Code에 동기화**되어 로드되고, 일반 대화에도 적용됩니다.
  - https://code.claude.com/docs/en/plugins/loading (Plugins synced from claude.ai)
- claude.ai에서 개인 마켓 추가 경로: Customize 메뉴 → Plugins 탭 → Personal plugins의 "+" → "Add marketplace" → 저장소에서 추가(GitHub 리포 또는 git URL)
  - https://support.claude.com/en/articles/13837440
- 결론: **이 리포를 마켓으로 만들고 claude.ai 계정에 연결하는 것이 클라우드 전용 사용자에게 사실상 유일한 공통 관리 방법**입니다.

### 3-3. 플러그인 목록을 얻는 방법
- `claude plugin list --json`: 설치된 플러그인 배열을 출력합니다. 항목마다 `id`, `version`, `scope`, `enabled`, `installPath`가 항상 있고, `scope` 값은 `user` / `project` / `local` / `managed` / `session` / `synced`입니다. `id`는 `name@marketplace`, 계정 동기화는 `name@synced`.
- 기본 내장 플러그인(`@builtin`)은 `claude plugin list`에 나오지 않습니다.
- `claude plugin details <이름>`: 플러그인 구성요소와 **세션마다 항상 붙는 토큰 비용(Projected token cost)** 을 보여줍니다.
  - https://code.claude.com/docs/en/plugins/cli-reference

### 3-4. 아직 검증되지 않은 것 (반드시 직접 확인)
- [x] 클라우드 세션 안에서 `claude` 명령이 PATH에 있고 `claude plugin list --json`이 정상 동작하는가 → 확인(2026-11-09, v2.1.319, 약 0.9초)
- [x] claude.ai 계정 플러그인(`@synced`)이 클라우드 세션에도 실제로 로드되는가 → 확인(`cowork-plugin-management@synced`가 목록에 나옴)
- [x] 계정 동기화된 플러그인 안의 훅(hooks/hooks.json의 SessionStart)이 클라우드 세션에서 실행되는가 → 확인(2026-11-09 새 세션)
- [x] SessionStart 훅의 출력이 Claude에게 맥락으로 전달되어, 첫 답변에 표를 띄우는 지시가 실제로 지켜지는가 → 확인(계정 연동 상태, 새 클라우드 세션 첫 답변에 표 + "설치된 플러그인 보여줘"도 동작)
- [x] 개인 마켓이 **공개 리포**여도 연결되는가 → 됨

### 3-5. 새로 알게 된 것 (2026-11-09)
- 지금 켜진 superpowers / ponytail / claude-md-management는 `@inline`, 범위 `session`. 출처는 **Default 클라우드 환경의 준비 스크립트**(세션마다 GitHub에서 최신판을 `/opt/claude-plugins`에 받고, 환경 변수 `CLAUDE_CODE_PLUGIN_DIRS`로 로드). 같은 스크립트가 `~/.claude/settings.json`(언어)과 `~/.claude/CLAUDE.md`(개인 지침)도 씀.
- 그래서 범위 값에 `session`이 하나 더 있음 → 표에서 "환경 자동설치"로 표시.
- 진열장 방식이 검증되면 준비 스크립트의 **플러그인 내려받기 부분만** 지우고, 언어·개인 지침 부분은 남긴다(같은 플러그인이 두 번 켜지는 것 방지).

### 3-6. 연결 때 겪은 함정 (2026-11-09)
- 데스크톱 앱 설정에서 추가한 직후 새 세션 2개에 플러그인이 안 들어옴. 웹 claude.ai의 "내 항목"도 비어 있었음. 웹에서 다시 추가하자 바로 반영(실행 중인 세션에도 들어옴). 데스크톱 쪽 추가가 계정 반영이 안 된 건지 지연인지는 불명 → **추가는 웹 claude.ai에서 하고 "내 항목"에 보이는지 확인**.
- `/reload-plugins`는 클라우드 세션에서 쓸 수 없음.

## 4. 결정 사항

- 리포 이름: `CastleQ/my-plugin-custom-management`
- 현재 **공개(public)** — 사용자가 Claude의 접근 문제를 우려해 일단 공개로 만듦. 연결·동작 확인 후 비공개 전환 여부를 사용자와 상의.
- 폴더 구조: `plugins/common`(항상 켬) / `plugins/optional`(필요 시) 분리. 항상 켜진 플러그인은 매 세션 토큰을 쓰기 때문.
- 색 구분(클라우드 기준):
  - 🟢 `synced` — 계정에서 동기화, 어디서나 동일
  - 🔵 `project` — 이 리포에서 켬
  - ⚪ 기본 내장
  - 회색(취소선 등) — `enabled: false`
  - (추가) 1차 버전은 색 대신 쉬운 국문 라벨: 계정 연동 / 환경 자동설치 / 이 리포 전용 / 이 리포(나만) / 내 PC 설정 / 관리자 지정 / (꺼짐). 색은 2차.
- 토큰 절약: 브리핑은 `startup` 때만, 표 몇 줄만 출력. 토큰 비용 표시는 2차에서 비용 자체도 따져보고 추가.
- "안 쓰는 플러그인" 자동 판정은 하지 않음. 클라우드 세션은 끝나면 기록이 남지 않아 세션을 넘는 사용 이력을 모으기 어렵기 때문. 대신 **매번 목록 + 토큰 비용을 보여줘서 사람이 알아채게** 함.

- 토큰 비용 표시(0.3.0): `claude plugin details`의 Always-on 추정치 사용. 훅이 끼워 넣는 글은 미포함(도구 자체가 "hooks: no model context cost"로 셈).
- headroom(headroomlabs-ai/headroom) 보류: 로컬 압축 프록시를 띄우는 방식이라 클라우드 세션에선 동작하지 않고, 확인용 훅이 Bash 실행마다 돎.

## 5. 다음 할 일 (순서대로)

1. **마켓 뼈대 만들기**
   - `.claude-plugin/marketplace.json` 작성 (마켓 이름은 리포 이름과 맞추기를 추천: `my-plugin-custom-management`)
   - `plugins/common/`, `plugins/optional/` 폴더
   - 작성 후 `claude plugin validate .` 로 검증
2. **session-briefing 플러그인 최소 버전**
   - 위치: `plugins/common/session-briefing/`
   - `.claude-plugin/plugin.json` + `hooks/hooks.json`(SessionStart 훅) + 스크립트 1개
   - 스크립트가 `claude plugin list --json`을 실행해 결과를 범위별로 분류하고, "첫 답변 맨 위에 아래 표를 보여줄 것"이라는 지시와 함께 출력
   - **1차 목표는 동작 확인**. 색 구분, 토큰 비용 표시는 동작이 확인된 뒤 2차로 추가
   - 실패해도 세션을 망가뜨리지 않게: `claude`가 없거나 오류가 나면 조용히 "목록을 가져오지 못함" 한 줄만 출력
3. **커밋·푸시**
4. **사용자에게 claude.ai 연결 안내** (비개발자 눈높이로, 클릭 순서대로)
   - 연결 후 새 클라우드 세션을 열어 브리핑 표가 나오는지 함께 확인
5. **공통 플러그인·스킬 목록 받기**
   - 사용자가 지금 모든 작업에 공통으로 쓰는 플러그인·스킬이 무엇인지 물어보고 `common`에 배치
6. **3-4의 미검증 항목** 결과를 이 문서나 README에 기록
7. 동작 확인 후 **비공개 전환 여부** 상의
